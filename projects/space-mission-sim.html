MISSION SIM · ORBITAL ANALYSIS
01
PROBLEM
Educational / pre-phase-A mission design needs a fast, browser-friendly way to play with orbital parameters, propellant budgets and timeline events without installing a full STK / GMAT stack.
02
ARCHITECTURE
Split frontend (React + Tailwind, deployed on GitHub Pages) and backend (FastAPI on Render). Configurable via .env. Frontend handles visualization and timeline scrubbing; backend runs propagators and returns structured mission events.
03
TECHNOLOGIES
ReactViteTailwindFastAPIPythonGitHub PagesRender
04
MY ROLE
Designer and full-stack developer.
05
CHALLENGES
  • ›Decoupling orbital math from the UI so the same backend can serve a web UI today and other clients later.
  • ›Keeping the bundle small and deployable on GitHub Pages while the backend runs on Render.
  • ›Designing a clean API surface for mission events, propagators and timeline scrubbing.
06
SOLUTION
A clean split: a React + Tailwind frontend on GitHub Pages for visualization and timeline scrubbing, and a FastAPI backend on Render that runs propagators and returns structured mission events. Configurable via .env, deployable with the included start.sh.
07
RESULT
A browser-based mission sandbox with a public landing page, live backend, and a clear separation between visualization and orbital math.
08
LESSONS LEARNED
  • ›Decoupling visualization from math lets you swap either side independently — useful for future mission types.
  • ›Tiny .env-driven deploys are easier to hand off than Dockerized monoliths.
